# BPF-Guardian RLVR Phase 1: VPS Runbook & Reproduction Guide

This document provides step-by-step reproduction instructions for setting up the Hostinger Linux VPS (`srv1534562`, `187.124.178.70`), executing the Qwen3-8B BPF RLVR Phase 1 pipeline, reproducing rewards, evaluating checkpoints, and auditing benchmark isolation.

---

## 1. System Architecture Overview

```text
┌─────────────────────────────────────────────────────────────┐
│                       TINKER CLUSTER                        │
│ - Qwen3-8B model sampling (T=0.8 for RL, T=0.0 for eval)   │
│ - LoRA rank 32 forward & backward passes                   │
│ - Importance sampling loss & group-relative advantages     │
│ - KL penalty regularization vs frozen SFT v2 checkpoint     │
│ - Optimizer updates (LR 5e-6) & checkpoint management       │
└──────────────────────────────┬──────────────────────────────┘
                               │ Token sampling & Gradients
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                    HOSTINGER LINUX VPS                      │
│ - Master RL controller (training/rl/train_rl.py)            │
│ - Kernel verification harness (KernelExecutor)              │
│ - Clang compilation (-target bpf -O2 -g)                    │
│ - Kernel verifier loading via bpftool (bpftool prog load)   │
│ - Packet execution via BPF_PROG_TEST_RUN (bpftool prog run) │
│ - Strict fail-closed cleanup & audit trail logging          │
└─────────────────────────────────────────────────────────────┘
```

**Security Mandate**: Untrusted C source code generated by the LLM is executed **only** on the Hostinger Linux VPS under strict isolated directory sandboxing. Code is never compiled or executed on Windows or Tinker cluster nodes.

## 2. VPS Runtime Provisioning

The target host is an Ubuntu 24.04 LTS VPS with native eBPF/XDP kernel capabilities.

### Prerequisites
- Kernel: `Linux 6.8.0-106-generic x86_64`
- Clang: `Ubuntu clang version 18.1.3 (1ubuntu1)`
- bpftool: `bpftool v7.4.0`
- libbpf: `libbpf v1.4`
- Python: `Python 3.12+` with virtual environment

```bash
# Connect to VPS
ssh -i ~/.ssh/hostinger.pem root@187.124.178.70

# Update packages and install core toolchain
apt-get update && apt-get install -y \
    clang-18 \
    llvm-18 \
    libbpf-dev \
    linux-tools-common \
    linux-tools-$(uname -r) \
    linux-headers-$(uname -r) \
    bpftool \
    git \
    python3-pip \
    python3-venv \
    curl

# Verify toolchain availability
clang --version
bpftool --version
uname -r
```

## 13. Recreating Rewards from Raw Verification Records

To verify that reward computation is completely deterministic and reproducible from raw disk records:

```bash
/root/BPF-FT-Project/.venv/bin/python -c "
import json
from pathlib import Path
from training.rl.reward import compute_rlvr_reward

records_dir = Path('runs/tinker/qwen3-8b-bpf-rl-v1/pilot/records')
for res_file in list(records_dir.glob('*/result.json'))[:5]:
    record = json.loads(res_file.read_text())
    recalc = compute_rlvr_reward(record)
    print(f'Rollout {record[\"rollout_id\"]}: Logged Reward={record.get(\"total_reward\")} Recalc={recalc.total_reward}')
"
```
